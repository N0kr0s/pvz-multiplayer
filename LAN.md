# Нативное LAN-лобби

Сеть и меню работают в C++ DLL внутри `pvzgame.exe`. Отдельный браузерный
прототип не используется для подключения этого лобби.

## Как подключиться

Оба компьютера должны иметь совместимую установленную widescreen-основу и
одинаковую версию мода. Перезапустите игру после обновления DLL.

1. Хост открывает MULTIPLAYER, выбирает HOST: PLANTS или HOST: ZOMBIES и нажимает HOST.
2. Игра создаёт TCP-сервер на свободном порту, выбранном ОС. В окне появляются
   IPv4 адреса активных интерфейсов и порт. Для друга нужен адрес интерфейса,
   подключённого к вашей общей локальной сети.
3. Клиент открывает JOIN, вводит IPv4 хоста и показанный порт, нажимает CONNECT.
   Щелчок по полю выбирает его; Tab переключает поля, Backspace удаляет символ,
   Enter подключает. Ввод поддерживает цифровые клавиши при любой раскладке.
4. При успешном обмене обе игры показывают CONNECTED — TWO PLAYERS. Клиент
   получает сторону, противоположную хосту. Ниже отображается время ответа.
5. DISCONNECT закрывает сессию. После ошибки TRY AGAIN возвращает выбор HOST/JOIN.
   BACK и Esc скрывают лобби, сохраняя активную сессию; повторный вход показывает её.

Проброс портов на маршрутизаторе для одной LAN не нужен. Если соединение
блокируется, входящий TCP на показанный порт должен быть разрешён на хосте.
Порт меняется при каждом новом HOST. Для проверки двух копий на одном ПК
можно указать `127.0.0.1`, для двух ПК нужен LAN IP.

Лобби проверено пользователем между Linux и Windows. Теперь добавлена
экспериментальная синхронизация штатного Board и кнопка START: подробности
и ограничения в [NATIVE_MATCH.md](NATIVE_MATCH.md).

## Две копии на одном Linux-ПК

Первую копию можно запустить из Steam, вторую — из каталога игры:

```bash
./multiplayer/test-instance.sh client
```

Либо откройте два терминала и запустите полностью отдельные тестовые профили:

```bash
./multiplayer/test-instance.sh host
./multiplayer/test-instance.sh client
```

Команды для двух терминалов; первая работает, пока открыта соответствующая игра.
Скрипт выбирает установленный Proton и запускает загрузчик нашего мода, затем
`PlantsVsZombies.exe` widescreen-мода и его дочерний `pvzgame.exe`. Widescreen-
загрузчик обязателен: прямой запуск дочернего EXE пропускает настройку 16:9.
Профили и mutex изолированы
в `multiplayer/test-data/host` и `client`, основные сохранения не используются.
При первом старте потребуется создать тестового игрока. Для удобства отключите
Full Screen в Options обеих копий. Запущенные тестовые копии сами не выбирают
HOST/JOIN: эти кнопки нужно нажать в игровом меню.

В клиенте укажите `127.0.0.1` и порт из окна хоста. Обе копии должны показать
CONNECTED и противоположные роли; оставьте их на 10 секунд, затем нажмите
DISCONNECT и проверьте сообщение у второго игрока. Также проверьте повторный
HOST/JOIN и обе стороны хоста. Это проверка лобби, не сетевого матча.

Логи тестовых копий: `pvzmp-test-host.log.menu`, `pvzmp-test-client.log.menu`.
Proton log находится в соответствующем `test-data/<instance>/steam-3590.log`.
Другую версию Proton можно выбрать переменной `PVZMP_PROTON` (путь к `proton`).
Скрипт и загрузчик собраны/проверены на уровне команд и путей; реальный запуск
двух окон в песочнице недоступен.

## Реализация

`hook/lan.cpp` — отдельный сетевой поток: Winsock на Windows/Proton,
POSIX на Linux для тестов. Поток не обращается к игровым объектам.
UI передаёт команды и получает копию состояния через критическую секцию.
Неблокирующие сокеты, `select` с ожиданием до 50 мс, корректная обработка
частичных чтений/записей TCP. Ожидание второго игрока не имеет тайм-аута;
подключение и handshake ограничены 8 секундами, отсутствие сообщений — 6 секундами.
Ping/pong отправляются раз в секунду. Третий клиент не заменяет занятую сессию.
IPv4 интерфейсы хоста определяются через Windows GetAdaptersInfo без DNS.

Кадр: 16 байт, четыре uint32 в сетевом порядке:
`magic=0x50565a4c`, `version<<16 | type`, `value`, `nonce`.
Текущая версия 2 (несовместима с 1); типы 1 HELLO, 2 WELCOME (value=сторона клиента), 3 PING, 4 PONG.
Игровые сообщения 10–16 и STATE с ограниченным телом описаны в NATIVE_MATCH.md.
Несовпадение версии/неожиданные сообщения завершают соединение.
Статусы и ошибки пишутся в `pvzmp-hook.log.menu`.

## Проверки

```bash
./multiplayer/hook/build.sh
./multiplayer/tools/test_lan.sh             # настоящий TCP loopback
./multiplayer/tools/test_lan.sh --simulated # имитация сокетов в ограниченной среде
```

Сборка Windows x86 DLL и тест на имитации проходят. Проверяются роли,
выделение порта, handshake, heartbeat, потеря соединения, повторное подключение,
лишний клиент, раздробленные чтения/частичные записи, молчащий клиент,
неверная версия, некорректный адрес и отказ подключения.
Имитация включается только тестовым define и отсутствует в DLL.

Реальный TCP-тест в текущей песочнице блокируется на создании сокета
(`EPERM: Operation not permitted`); соединение двух запущенных игр и новый
экран ввода ещё требуют проверки вне песочницы.

## Проверка Linux + Windows

Для проверки на двух компьютерах используйте обычный запуск Linux-хоста из Steam.
На Windows установите такую же widescreen-основу, распакуйте архив мода
в каталог игры и при открытом Steam запустите `multiplayer/start-windows.cmd`.
CMD сначала запускает `install-menu.exe`: он применяет `assets/menu.patch` к
двум записям PAK, сохраняя исходник в `multiplayer/backups/before-native-menu.pak`.
Патч включает компоновку анимации меню и регистрацию PNG. Все прочие записи
сохраняются. Повторная установка допустима; чужая версия/повреждённый патч
отклоняются. Затем CMD задаёт AppID и запускает наш загрузчик; тот запускает штатный widescreen-
загрузчик и внедряет DLL в его дочерний игровой процесс. Баш-скрипт на Windows
не нужен. Нативный запуск на Windows ещё не проверен.

На Linux выберите HOST, на Windows — JOIN. Введите LAN IPv4 и порт, показанные
хостом. Адрес 127.0.0.1 для двух компьютеров не подходит. Обе машины должны
быть в общей доступной локальной сети. Нужна одинаковая версия DLL и ресурсов.

Проверьте CONNECTED, противоположные стороны, соединение в течение 30 секунд,
DISCONNECT, повторный вход. Для проверки общего поля после соединения нажмите START на хосте; см. NATIVE_MATCH.md.

## Переключение рабочих столов и буфер обмена

Пользователь подтвердил: зависание воспроизводится при ручном тестовом запуске,
а при обычном запуске из Steam не возникает. В тестовых профилях установлен
Proton 11.0 и ScreenMode=1 (полноэкранный режим). Точная причина различия
окружений пока не установлена. Для дальнейшего тестирования выбран Steam-хост
и отдельный Windows-клиент.

Предыдущий обход WM_ACTIVATEAPP не устранил зависание и удалён. Штатные события
активации снова передаются игре. Диагностика сохранена: начало/завершение
событий окна и отсутствие обновлений меню более трёх секунд. Последний журнал
показал завершённые обработчики окна, stage=0 и периоды возобновления кадров;
это не подтверждает зависание непосредственно внутри обработчика фокуса.
Настройки Hyprland/Omarchy не менялись.

## Ошибка ресурсов при первой Windows-установке

Первый preview-архив не включал автоматическое применение PAK-патча.
Чистая widescreen-основа не содержит IMAGE_MP_PLAQUE / IMAGE_MP_LABEL;
вызов ResourceManager::GetImageThrow для них может закончиться C++-исключением
0xe06d7363. Этот код сам по себе не определяет причину любого сбоя Windows.
Начиная с этой версии CMD применяет патч перед запуском игры, Python на Windows
не требуется. Нужно заново перенести актуальный архив и заменить файлы мода.

Исходник установщика: `tools/install_menu.cpp`. Он использует только штатные
Windows DLL и CRT; ядро патча также собирается под Linux для проверки.
Подготовка `assets/menu.patch`: `python3 multiplayer/tools/build_menu_patch.py`
на рабочей установке с исходной резервной копией. Патч содержит проверяемые
XOR-разности двух записей, а не готовый игровой PAK.

Ядро установщика проверено на исходном PAK: результат побайтно совпадает с
рабочим PAK; повторная установка даёт тот же файл, повреждённый патч отклоняется.
Windows-оболочка собрана в PE32; её выполнение на реальной Windows пока не проверено.


### Linux-хост и UFW (протокол 5)

Новый архив — `releases/pvzmp-native-gameplay-preview.zip`, детали — [NATIVE_MATCH.md](NATIVE_MATCH.md).
Порт выбирается автоматически из TCP 35900–35909. Один раз выполните в терминале
Linux-хоста `bash multiplayer/tools/allow-linux-host.sh`: скрипт через sudo добавит
правило UFW только для подключённой LAN-подсети. Firewall не отключается.
На обоих ПК необходима новая DLL. Проверка с Windows при открытом HOST:
`Test-NetConnection IP_ХОСТА -Port ПОРТ_ИЗ_ИГРЫ`.
